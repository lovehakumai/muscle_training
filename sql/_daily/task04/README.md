# 💻 シニア・データエンジニア（テックリード）からの挑戦状 #4

## 今回選んだテーマ: 日付操作のエッジケースとISO週番号・年をまたぐ集計の罠

### 業務要件（シナリオ）の要点：
* 毎週火曜日に「**先週の月曜 00:00:00 〜 日曜 23:59:59**」の確定売上を集計する週次レポートバッチを構築します。
* **曜日の実行タイミング（月曜実行か火曜実行か）**や、**年末年始のまたぎ（カレンダー年とISO年の不整合）**が起きても、データ欠損や二重集計を一切出さない、決定論的（Deterministic）な日付境界ロジックを作ってください。
* **`2025-12-29`（月）〜 `2026-01-04`（日）** という年をまたぐ週であっても、基準日（実行日）から100%正確に「先週（月〜日）」の範囲を切り出す必要があります。

### 制約条件：
1. **実行環境に依存する動的関数の禁止**: `CURRENT_DATE()` や `CURRENT_TIMESTAMP()` は使わず、基準日として与えられる変数（セッション変数や定数リテラル `'2026-09-01'` または `'2026-01-06'`）から逆算する構造にすること。
2. **Sargable（パーティション刈り込み可能）な範囲指定**: `sale_timestamp` カラムそのものを `DATE_TRUNC` などの関数で加工しないこと。
3. **ISO週基準での正確な週境界の算出**: Snowflakeのパラメータによる曜日設定の揺れに依存せず、常に「月曜〜日曜」の境界を算出すること。
4. **CTEは2段階まで**。

### DDL & サンプルデータ（そのまま実行可能）
前回の「`VALUES`句の関数制約」をクリアするため、`UNION ALL`型で定義しています。

```sql
CREATE OR REPLACE TRANSIENT TABLE raw_weekly_sales (
    sale_id VARCHAR,
    sale_timestamp TIMESTAMP_NTZ,
    amount DECIMAL(10,2)
);

INSERT INTO raw_weekly_sales (sale_id, sale_timestamp, amount)
SELECT 'S_001', '2026-08-23 23:50:00'::TIMESTAMP_NTZ, 100.00 -- 2026-08-23 (日) -> 対象外（先々週）
UNION ALL
SELECT 'S_002', '2026-08-24 01:10:00'::TIMESTAMP_NTZ, 200.00 -- 2026-08-24 (月) -> 対象（2026-09-01実行時）
UNION ALL
SELECT 'S_003', '2026-08-30 15:00:00'::TIMESTAMP_NTZ, 150.00 -- 2026-08-30 (日) -> 対象（2026-09-01実行時）
UNION ALL
SELECT 'S_004', '2026-08-31 09:00:00'::TIMESTAMP_NTZ, 300.00 -- 2026-08-31 (月) -> 対象外（実行週の売上）
UNION ALL
-- 年末年始の境界エッジケース
SELECT 'S_005', '2025-12-28 18:00:00'::TIMESTAMP_NTZ, 500.00 -- 2025-12-28 (日) -> W52（2026-01-06実行時の対象外）
UNION ALL
SELECT 'S_006', '2025-12-29 10:00:00'::TIMESTAMP_NTZ, 400.00 -- 2025-12-29 (月) -> 2026年W01の始まり（2026-01-06実行時の対象）
UNION ALL
SELECT 'S_007', '2026-01-04 23:00:00'::TIMESTAMP_NTZ, 600.00 -- 2026-01-04 (日) -> 2026年W01の終わり（2026-01-06実行時の対象）
UNION ALL
SELECT 'S_008', '2026-01-05 08:00:00'::TIMESTAMP_NTZ, 700.00; -- 2026-01-05 (月) -> 2026年W02（2026-01-06実行時の対象外）
```
