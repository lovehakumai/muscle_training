# 2026-09-05 SQL Daily

前回の指摘：GROUP BY抜けによる0件入力時の罠、およびCTE内での無意味なORDER BYの復習

今回選んだテーマ: 遅延データのハンドリング（QUALIFY句での重複排除）

## シナリオ

各店舗からの日次売上データが送られてきます。しかし、システム障害による再送（遅延データ）が発生するため、同じ `store_id` と `sales_date` の組み合わせで複数レコードが届くことがあります。
最新の `received_at` のレコードのみを正しいデータとして採用し、**'2026-09-01' の1日分の売上合計金額**を集計してください。結果には `sales_date` と合計金額を含めてください。

## 制約条件

✓ 重複排除には `QUALIFY` 句を使用すること（重複排除のための CTE 内での GROUP BY やサブクエリは禁止）
✓ CTE は 1段階まで
✓ もし対象日（2026-09-01）のデータが1件もなかった場合、`(NULL, NULL)` のような行を出力するのではなく、「0行」が返るように適切な句を用いて集計すること
✓ CTE内で最終結果の順序を保証しない無意味な `ORDER BY` を書かないこと

## テーブル定義（DDL & サンプルデータ）

`setup.sql` と同じ内容。

```sql
CREATE OR REPLACE TABLE raw_daily_sales (
    store_id VARCHAR,
    sales_date DATE,
    amount NUMBER,
    received_at TIMESTAMP_NTZ
);

INSERT INTO raw_daily_sales VALUES
    -- 2026-08-31: 対象外の日付
    ('store_A', '2026-08-31', 1000, '2026-08-31 20:00:00'),
    
    -- 2026-09-02: 対象外の日付。通信遅延による重複再送あり
    ('store_B', '2026-09-02', 1500, '2026-09-02 21:00:00'),
    ('store_B', '2026-09-02', 2000, '2026-09-02 23:00:00'); -- こちらが最新
    
    -- 2026-09-01: 本来の集計対象日だが、レコードが1件も存在しない（0件入力の罠）
```
