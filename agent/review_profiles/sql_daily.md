`sql/_daily/task_d_{NN}/` のレビューで、手法ファイル（`review_1_correctness` / `review_2_quality`）と**併せて読む。**

机上トレースで導き、**実行していないことをレビュー冒頭に明記する。**

## 読む対象

| ファイル | 目的 |
|---|---|
| `README.md` | 課題文。要求と制約 |
| `my_answer.sql` | **提出版。レビューの主対象** |
| `setup.sql` | DDL とサンプルデータ。**机上トレースに必須**（どの行がどう扱われるかを確定させる） |

dbt は使わない前提（ワークシートで実行できる単一クエリ）。`models/` や `dbt_project.yml` は存在しない。

## 正確性の観点

- **境界値** — `BETWEEN` が両端を含むことによるオフバイワン。半開区間 `>= start AND < end` になっているか
- **境界の正規化** — 基準日に時刻成分が乗る場合、`DATE_TRUNC` で正規化しているか。**カラム側**を加工していないか（プルーニングが崩れる）
- **重複排除の粒度** — `PARTITION BY` のキーが業務上の一意粒度と一致しているか。サンプルデータでは露見しない欠損を疑う
- **同点（tie）** — `ROW_NUMBER` はソートキーが同値なら順位を保証しない
- **0件入力** — `GROUP BY` の無い集計クエリは**0行入力でも1行返す。** 集計関数が NULL になり `(NULL, NULL)` が出る
- **NULL の伝播** — 集計関数の NULL 除外、`NOT IN` に NULL が混ざると全件消える、`CASE` の `ELSE` 漏れ
- **暗黙の型変換** — DATE と TIMESTAMP、VARCHAR と NUMBER の比較。動くが意図とずれる、あるいはプルーニングが効かなくなる
- **結合による膨張（fan-out）** — 1対多の結合で行が増え金額が二重計上される

## イディオム・パフォーマンス

- Window関数 / `QUALIFY` の適切な使用。不要なサブクエリ・CTE
- **集約前の `ORDER BY`** — 順序を保証しないうえ、全件ソートは最もスピレージを起こしやすい
- **窓関数の前に絞り込めているか** — `WHERE` が窓関数の後（外側）にあると全件に対して `ROW_NUMBER` が走る
- **Sargable か** — カラムに関数を適用するとパーティションプルーニングが効かない
- 冗長な構造 — `CASE WHEN <boolean> THEN true ELSE false END` は条件式そのものと同じ。発動しえない `NVL` / `COALESCE`

## 命名

- 境界は開始と終了のペアで対称に（`baseline` 単独ではなく `week_start_date` / `week_end_date`）
- **粒度と型を名前に入れる**（`week` は週番号か日付か不明）
- **層を示す接頭辞を誤用していないか** — `raw_` / `stg_` / `int_` / `fct_` / `dim_` は層の規約。処理ステップ名の CTE に `raw_` を付けると生データ層と誤読される
- CTE 名が実体を反映しているか。**名前が実装の誤解を映していることがある**（「日付単位で最新」を意味する名前なのに `PARTITION BY store_id` だけ、など）

## 本番運用の必須トレース

| 観点 | 何を見るか |
|---|---|
| **0件入力** | 対象期間にデータが無いとき、何行返り中身はどうなるか。`(NULL, NULL)` を返さないか |
| **冪等性・決定論性** | 同じ入力・同じ基準日で必ず同じ結果か。同点時の順位が決まっているか |
| **バックフィル** | 対象期間を外から渡せるか。セッション変数化されていれば**問題なしと書いてよい** |

そのほか：境界そのものを検証するアサーション（`span_days = 7`、`start_dow = 'Mon'` を確認するクエリ）の有無。

## 修正版スクリプトの出力

`FB_from_AI_{NN}/corrected_answer.sql` として**1ファイル**で置く。

- 指摘した全項目と課題文の全制約を**同時に満たす**こと（CTE の段数を数え直す）
- 冒頭コメントに差分を列挙。**実際に変更した行だけ**を挙げる
- **実行していないことを明記する**
- `SET` 文に依存する解は単一 SELECT にならないため dbt モデルには移植できない。Daily では許容だが、その旨を1行添える
