## 正確性の観点

- **同点（tie）** — 「最大値の行を取る」で同点があると、どの行が残るか決まっているか。`sort_values` の既定 `kind='quicksort'` は**非安定**。ただし**ソートキーの組が一意なら `kind` は無関係**（この区別ができているかは理解の証拠）
- **index の扱い** — `df.index` を値として使う前に `reset_index(drop=True)` しているか。`pd.concat` 後は index が重複しうる
- **0件入力** — 空の DataFrame が静かに返って「正常終了」しないか。上流の停止を検知できるか
- **NaN / NULL** — `nunique()` と `count()` は NaN を除外、`len()` と `.size` は含む。`drop_duplicates` は NaN を1つの値として残すが `groupby` は既定で除外する（**同じデータで件数が食い違う**）
- **dtype** — `astype(str)` は NaN を文字列 `'nan'` に変える（**エラーが出ないまま壊れる**）。`astype('string')` なら pd.NA を保つ。`category` への `fillna` は未定義カテゴリだと失敗する。`int` 列に NaN が入ると `float` に昇格する
- **文字列日付** — 辞書順ソートが時系列順と一致するのは ISO 8601 のときだけ
- **検証が機能しているか** — 実装と同じ操作で期待値を作っていないか（詳細は手法ファイル）

## イディオム・パフォーマンス

- pandas API の適切な使用。**ループでの逐次処理**になっていないか、`apply` の濫用、chained indexing
- **捨てられる `.copy()`** — 作った直後に別オブジェクトで上書きしていないか。判定基準は「**その変数を書き換えるか**」だけ。`df[...] = ` や `inplace=True` を書くなら必要、読むだけなら不要
- **`category` の round-trip** — `astype('string')` を経由して `category` に戻すと、未出現カテゴリの定義と順序が失われ、**全値を文字列として実体化するので category のメモリ削減効果を一時的に破棄する**。`.cat.add_categories()` が正攻法
- 冗長な構造 — `CASE`相当の `np.where` の濫用、発動しえない `fillna`、no-op の自己代入

## 命名

- 変数名が中身を説明しているか。**`tmp_` は「一時変数である」ことしか言っていない**（関数ローカルは全部一時変数）
- 関数が名前より多くの責務を持っていないか（`cleanse_data` が抽出も検証もしていないか）
- 引数名がモジュール変数と同名になっていないか（シャドーイング）
- 型ヒントがあるか

## 本番運用の必須トレース

| 観点 | 何を見るか |
|---|---|
| **0件入力** | 空の DataFrame で落ちるか、静かに空を返すか。後者なら検知手段があるか |
| **冪等性・決定論性** | 同点時の順位、出力の行順と index が固定されているか |
| **バックフィル** | 対象期間・対象日を引数で受け取れるか（該当しない課題では「期間指定に依存する処理はない」と書く） |

そのほか：`assert` を品質ゲートに使っていないか（**`python -O` で削除される**。データの異常は `raise`）、握りつぶして終了コード0を返していないか、宣言されていない依存。
